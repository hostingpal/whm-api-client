# ImageManager root-list batch failure correction

This bounded review correction prevents successful dimension reads from failing payload validation and preserves per-file thumbnail failure reasons. The owner's standing ordered review/fix authorization covers this implementation choice; it introduces no endpoint or live action.

The pinned `get_dimensions` fields remain optional integers. Add the existing explicit `numeric-string` acceptance only to height/width, with attributed review5724933500 source/wire evidence and independent literal fixtures. No request conversion or global normalization is added.

For `create_thumbnails`, use Unchecked plus existing string rows descriptor `'$'` to select the whole payload only when the declared root is a nonnullable list of nonnullable objects. Existing object-field selectors, including any literal field name, retain their object-root interpretation. Effective building requires exact selected-source SHA/data-schema-pointer evidence for the root list; PHP spec validation enforces the same shape, UAPI/Unchecked scope and no optional/unwrap/void bypass. The generator emits the existing string descriptor; no new descriptor type is needed.

Typed outcome integer validation precedes classification. Under status0, explicit null retains the established opted-in no-rows API-error classification; a completely validated empty root list also raises the same ApiErrorException. Valid nonempty lists return all rows, including all-failed batches. Missing data, wrong roots, malformed known row fields and nullable/malformed items remain PayloadMismatchException with outcomeConfirmed=false. Status1 retains the original strict schema, optional fields and valid empty list. Outer WHM failure still takes precedence. No policy applies to other Unchecked/generic/Flag calls. Fileman's named uploads policy remains exact.

Alternatives considered: a separate root_rows boolean would duplicate policy plumbing, while a generalized selector/expression grammar would broaden scope. Reusing the existing rows string with a shape-qualified root selector is the smallest additive choice. The cost if wrong is special root-selector documentation and another future result shape needing its own provenance review; no public method contract changes.
